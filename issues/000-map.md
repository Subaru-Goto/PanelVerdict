## Destination

A demo-able, **text-only** PanelVerdict **v1** — the first complete build. The full loop end to end: two headlines + a natural-language target audience in → a Bayesian verdict with reasons out. It covers everything the project needs to count as "done for v1" — a domain-specialised chatbot + advanced RAG (delivered as query translation / structured retrieval over the persona pool) + ≥3 tools + a Next.js report UI + the technical & security pieces — the **panel** running on one cheap model (GPT-5 Mini; the **analyst** uses a separate reasoning model — see [003](003-decide-panel-model-and-provider.md)).

## Notes

- **Domain:** synthetic-panel A/B testing for content/marketing creative. Full product vision lives in `docs/project-idea.md` — treat it as a **living draft**: resolving a ticket may mean editing it.
- **This is an EXECUTION-CARRYING map, not plan-only** (Wayfinder default overridden here). Decision tickets (`wayfinder:grilling` / `wayfinder:research`) resolve open questions; `wayfinder:task` tickets carry the actual **build** through to a demo-able app. Build tickets use a `## Goal` body instead of `## Question`.
- **Skills to consult:** `/grilling` + `/domain-modeling` for decision tickets; `/prototype` where a UI/logic sketch clarifies; the langchain / langgraph skills for build tickets; `/research` for research tickets.
- **Bayesian scope for this map:** FLAT binary Beta-Binomial + full posterior report (P(B>A), expected lift + 95% CrI, expected loss, ROPE verdict) + adaptive stopping. Hierarchical and zero-inflated models are OUT (B-era).
- **Vote-schema forward-compat (superseded by [002](002-decide-vote-schema.md)):** v1 vote is a **forced binary {A, B}** (no `neither`), represented as a **variant *reference*** so **multivariate (v2)** is a data change, not a schema change. `neither` + the zero-inflated model are deferred *whole* to B-era — a schema **addition** then, not a rewrite. Votes are **model-blind + positional** with counterbalanced, stored order. (Earlier plan to capture {A,B,neither} from day one was dropped — see 002.)
- **Target:** first complete build in ~2 weeks (≈ 2026-07-30) — a personal milestone, not a hard external gate.

NFC/maximizing/CSII deferred to *earn via the manipulation check*; mood + past-behavior dropped. Grounded in [research](../docs/research/persona-attributes-grounding.md). **Amended 2026-07-17:** correlated sampling + gender promoted into v1 (were v2); aspects/facets deferred pending a quality check; seed-data sourcing → a research step in 006. **Amended 2026-07-21:** v1 is **multi-region** (seed JP/US/DE); **country** is the grounding key with a derived **culture_tag** for coarse targeting (no "Asian"/"Western" census); Big Five μ stays **shared age/gender contrasts** — country does *not* condition trait means (reference-group effect); **language** is model-native + frontend i18n, not a generation channel. **Amended 2026-07-26:** v1 persona = **demographics + Big Five**; `interests` is dropped after four failed designs (see [006j](006j-persona-summary-embedding.md)), and the RAG requirement's vector half runs on a templated persona-summary embedding of those two instead.
- [Decide the panel vote + structured-output schema](002-decide-vote-schema.md) — **forced binary {A, B}** (no `neither`), choice stored as a **variant reference** (→ multivariate v2 without a schema change). Model emits an **identity-blind positional** vote + a content-based free-text `reason`; system stores `chosen_variant_id` + counterbalanced `presentation_order`. Flat Beta-Binomial over choosers. **Reproducibility** designed in: test-retest via temp≈0 + seeded pool + pinned model; sample-stability via representative sampling + adaptive stopping, judged *within credible intervals*.
- [Decide panel model + OpenRouter provider config](003-decide-panel-model-and-provider.md) — panel = **`openai/gpt-5-mini`** via **OpenRouter** + prompt caching (≈$0.055/200-persona test; Haiku 4.5 fallback), benchmarked for Big-Five enactment against flagship **GPT-5.6 Sol** (final pick confirmed-or-revised by the manipulation check). **$10 per-key cap** (402 hard-stop → pre-flight check + partial-run handling + resume via the 002 vote-cache). Dev ladder **stub → nano → mini** (model is config, never hardcoded). Analyst = a **reasoning model** → deferred to [012](012-build-analyst-chatbot-tools.md). Live pricing: [research](../docs/research/panel-model-selection.md).

- [Persona summary embedding: drop interests, embed demographics + Big Five](006j-persona-summary-embedding.md) — `interests` dropped after four failed designs; fuzzy targeting runs on a **templated persona-summary embedding** of demographics + Big Five, rendered at **five** trait levels instead of three (three discarded the continuous sampling 006c pays for). The pool becomes a pure function of `master_seed`, so the database is a cache and drop-and-reseed replaces migrations. Slice 4's ablation graduated to [Targeting manipulation check](014-targeting-manipulation-check.md).

- [Targeting manipulation check: does a persona attribute move a vote?](014-targeting-manipulation-check.md) — **yes.** Temperament changes **32.5%** of votes against a ~11% noise floor, with clean controls (trait-free arm flat; no trait moves the control pair). Openness, conscientiousness and extraversion each carry the vote never→always; agreeableness weaker but ordered; the neuroticism *pair* is broken by a 1.00 baseline, so that trait is untested. Three vs. five levels: no detectable difference at this power. Confirms the 003 model pick, measures position bias at 0.66 for 002, and makes 001's earn-their-place gate usable. [Results](../docs/research/manipulation-check.md).

- [Build the persona pool (generate + persist with embeddings)](006-build-persona-pool.md) — **closed**; every child resolved. 5k/200 pool sampled from the OECD joint tables + correlated Big Five, persisted to Postgres/pgvector with one summary embedding each, seeded idempotently. `interests` never shipped (see 006j). Pool QC ([006g](006g-pool-overview.md)) compares each country against its own table and the traits against priors *conditioned on the realized age/gender mix* — the naive `mean 0, sd 1` check would fail a correct sampler, since μ moves with age and gender. Dev pool's worst of 64 comparisons: z = +2.38.
- [Task-framing sensitivity](015-task-framing-sensitivity.md) — the verdict is **framing-dependent at the vote level** (38–43% of matched votes flip between questions, against a ~0.21 floor) and **framing-stable at the verdict level** (the openness gradient is identical under all three). `preference` stays shipped, for want of grounds to change it. The larger finding is a **failed validity check**: the panel's strongest, most consistent preference falls on a lever that published field data says does nothing, while the three levers that do move real clicks land at chance — so the panel is **unvalidated on same-meaning copy**, which is the regime real A/B tests live in. [Write-up](../docs/research/task-framing.md).

## Not yet specified

<!-- in-scope fog toward the destination; graduates into tickets as the frontier advances -->

- **Does the panel reproduce *any* published copy effect?** [015](015-task-framing-sensitivity.md) found agreement at chance across three Gligorić levers, but with one sentence pair each — so "the lever" and "that sentence" are confounded and the result removes an assumption rather than settling the question. The sharp version needs several pairs per lever; what is not yet sharp is how many, and whether it is worth running before the Upworthy validation study it is a cheap rehearsal for.
- **Rewriting the stimulus set.** Four of the six headline pairs have no-persona baselines above 0.85 or below 0.10, which compresses the range a manipulation can move through, and the neuroticism pair is saturated at 1.00 outright. Sharp enough to ticket: replace the neuroticism pair and rebalance the rest toward a 0.5 baseline, then re-run. What is *not* yet sharp is whether that is worth doing on its own or only alongside the next thing.
- **Do the traits still work in combination?** The sweep varies one trait and pins the other four at medium; every real persona carries five levels at once, drawn correlated. Two candidate designs — an orthogonal two-way factorial (clean interaction estimates) or a regression over personas sampled from the actual pool (realistic, but the pool's Σ makes the coefficients collinear) — and the choice depends on whether interactions or population-level survival is the worry. Also unaddressed: demographics were held fixed throughout, so nothing is known about whether age, income or education move a vote.

- **Reason clustering** (embed + cluster rationales) — in v1's report, or just a flat reason list? Graduates once the report-UI ticket is worked.
- **Gap-fill persona generation at test time** — build it in v1, or rely purely on the pre-generated pool? Depends on how well the pool covers real target descriptions.
- **DeepEval / CI scope** — which pipeline-QA tests (structured-output validity, position-bias regression, **test-retest + sample-stability reproducibility checks** from [002](002-decide-vote-schema.md)) are needed to satisfy the "technical implementation" requirement.
- **Panel sampling procedure** — how a panel is drawn from the 5k pool for a given target so draws are representative *and* comparable across samples (feeds sample-stability); graduates with the persona-pool / targeting build (006/007).
- **Demo delivery** — localhost walkthrough vs. deployed unguessable link; hard per-key budget caps either way.
- **Exact "Ask the analyst" suggested-question chip set** — graduates once the pipeline API and report shape exist.

## Out of scope

- **Fixing the same-meaning validity gap — deferred to v2 (decided 2026-07-27).**
  [015](015-task-framing-sensitivity.md) showed the panel produces confident
  preferences uncorrelated with published field effects when two variants mean the
  same thing. Closing that needs external validation against real outcomes (the
  Upworthy study), which is already out of scope here, plus very likely prompt or
  model work downstream of it. v1 ships with the measured caveat carried in the
  report ([011](011-build-report-ui.md)) rather than with a fix.

- **A — the Upworthy validation study & result.** Its own later map; the product's differentiator and the gate for the RAG knowledge base.
- **Audience-research RAG knowledge base** — gated on A's ablation result (does grounding improve accuracy?). The RAG requirement itself is already met by persona-pool retrieval, so this corpus is a value-add, not a requirement.
- **Images / VLM evaluation** — B feature.
- **Sub-national region + election-prediction use case** — B-era. v1 drops within-country region; **B-era can add it cheaply** (additive `region` column + migration; US-first from **ACS PUMS geography we already sample then discard**, so it stays congruent-by-construction — NY inherits its more-educated/urban mix automatically). Election prediction reuses the **existing A/B engine** (D vs R = option_1/option_2; politics is a preference the LLM infers from the persona, no political "flag" field for the *mechanism*), but for *accuracy* it additionally needs: (a) the high-signal fields v1 omits — **race/ethnicity, religion/religiosity, urbanicity**; (b) an **"others"/abstain** path beyond the forced binary; (c) **validation against real returns** — unlike marketing A/B (an unfalsifiable preference simulator), a forecast is falsifiable, and LLM political priors are a documented weak spot (stale realignment, flattened distributions).
- **Hierarchical Bayesian, the zero-inflated model, and the `neither` vote option** — all B-era. v1 is binary {A, B}; adding `neither` later is a schema **addition**, not a rewrite (see [002](002-decide-vote-schema.md)).
- **Auth, payments, multi-provider** — future; not even B.
